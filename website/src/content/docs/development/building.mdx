# Building from Source

Openza Flow is a Windows-native WinUI 3 app.

## Prerequisites

- Windows 10 22H2 or Windows 11
- .NET 10 SDK
- Visual Studio 2026 Community or newer with the Windows App SDK / WinUI workload
- Windows SDK 10.0.26100 or newer
- PowerShell 7+

## Build Steps

<Steps>
1. Clone the repository.

   ```powershell
   git clone https://github.com/openza/flow.git
   cd flow
   ```

2. Restore and run tests.

   ```powershell
   dotnet restore src\Openza.Flow.Tests\Openza.Flow.Tests.csproj
   dotnet test src\Openza.Flow.Tests\Openza.Flow.Tests.csproj -c Release --no-restore
   ```

3. Restore and build the app.

   ```powershell
   dotnet restore src\Openza.Flow\Openza.Flow.csproj
   dotnet build src\Openza.Flow\Openza.Flow.csproj -c Release --no-restore
   ```
</Steps>

## Debugging

Use Visual Studio for packaged debugging:

- Set `Openza.Flow` as the startup project.
- Choose the `Package` profile.
- Enable Deploy for `Openza.Flow` in Configuration Manager.

<Aside type="note">
  Command-line `dotnet run` can build a WinUI app but packaged features such as app identity, startup tasks, and toast activation need packaged debugging or an installed MSIX.
</Aside>

## Store Package

Use Visual Studio's Create App Packages flow after associating the project with the Microsoft Store app name. The repository intentionally ignores generated certificates, MSIX packages, and upload artifacts.
