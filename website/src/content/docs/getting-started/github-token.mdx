# GitHub Sign-in

Openza Flow needs a GitHub credential to read pull request, release, and workflow-run metadata for your account. You can use GitHub OAuth device flow or a Personal Access Token.

## Sign in with GitHub

This is the recommended path.

<Steps>
1. Launch Openza Flow.
2. Select **Sign in with GitHub**.
3. Open the GitHub device activation page when prompted.
4. Enter the code shown in Openza Flow.
5. Authorize the app and return to Flow.
</Steps>

<Aside type="tip">
  The OAuth client ID is public app metadata, not a secret. The access token is stored locally in Windows Credential Locker.
</Aside>

## Personal Access Token

Use this fallback if OAuth is not suitable for your environment.

<Steps>
1. Select **Use personal access token**.
2. Create a token from GitHub Developer settings.
3. Grant access needed for the repositories you want Flow to show. Classic tokens should include `repo` or `public_repo`, plus `read:user` and `read:org`.
4. Paste the token into Openza Flow and connect.
</Steps>

<Aside type="caution">
  Treat PATs like passwords. Do not share them and do not commit them to source control.
</Aside>

## Storage

Tokens are stored in Windows Credential Locker. Openza Flow does not sync credentials to Openza servers and does not migrate credentials from the legacy Flutter app.

Draft releases appear only when GitHub returns them for the signed-in account's permissions. Releases and Actions views are read-only and open GitHub for details.

## Sign Out

Open Settings in Flow and select **Sign out**. This removes the stored token from Windows Credential Locker and returns the app to the sign-in screen.
